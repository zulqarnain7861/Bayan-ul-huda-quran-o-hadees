PART 1 - SMART NEXT / PREVIOUS NAVIGATION FOR HADITH BOOKS
Applies to Sahih al-Bukhari, Sahih Muslim, Sunan Abi Dawud, Jami' al-Tirmidhi, Sunan al-Nasa'i, Sunan Ibn Majah, Muwatta Imam Malik, Musnad Ahmad, Sunan al-Darimi, Riyad al-Salihin, Al-Shama'il al-Muhammadiyyah, Bulugh al-Maram, Al-Adab al-Mufrad, Mishkat al-Masabih, the Forty Hadith collections and every collection added in Part 2.

Sequence model
- Build one ordered navigation index per collection: collection -> book -> chapter -> hadith position -> record id. Next loads index + 1, Previous loads index - 1.
- Never derive the next record from the visited-history list, never jump to hadith numbers or pages already visited, and never load arbitrary records such as 3, 5 or 7 because of earlier visits.
- Navigation must cross chapter, volume and juz boundaries without gaps, repeats or duplicates.
- Keep one reading-state object (collection, book, chapter, hadith number, scroll position) that survives rotation, process death and app restart.

Next button
- If online, fetch exactly the next record from the source API or dataset using cursor or offset pagination that matches the source ordering.
- Validate collection id, hadith number and record id before display. Reject mismatches and log them instead of showing wrong content.
- Cache every successfully fetched record into the existing offline store for later use.
- Do not re-download whole books, do not pre-fetch unrelated chunks just to skip ahead, and do not repeat identical network calls.

Previous button
- Same logic in reverse: load exactly index - 1 with the same validation, the same cache read and the same reading-state update.

No-internet behaviour
- Check real connectivity before requesting content.
- If offline, show this popup:
  Title: No Internet Connection
  Message for Next: "Internet connection is unavailable. Would you like to load the available preloaded content for the next Hadith/page?"
  Message for Previous: "Internet connection is unavailable. Would you like to load the available preloaded content for the previous Hadith/page?"
  Buttons: "Load Preloaded Content" and "Cancel".
- On Load Preloaded Content: retrieve exactly the next or previous available record from the offline database, keep the sequence intact, label it visibly as preloaded/offline, and never substitute a different record.
- On Cancel: dismiss the popup and keep the current hadith, chapter and scroll position unchanged. No request, no state change.
- If no offline record exists for that exact position: state clearly that internet is required and that no preloaded content is available for this page. Do not navigate anywhere else.

Four separate states - never confuse them
1. Book availability: does this collection or book exist in the app at all.
2. Internet connectivity.
3. Online content availability: did the source return this record.
4. Preloaded content availability: is this exact record cached.
Never tell the user that the Hadith book or the library is unavailable merely because the connection dropped. A genuinely missing book gets a book-unavailable message. A missing cache entry gets the "internet required, no preloaded content for this page" message.

Data integrity during navigation
- No duplicate records, no skipped hadiths, no repeated hadith numbers, no cross-collection leakage.
- Never fabricate, rewrite, paraphrase or silently substitute Arabic text, translation, grading or references.
- Log a navigation trace (collection, from id, to id, online or cache) for the final report.

UI
- Keep the existing interface and design. Use the existing Next and Previous buttons. No new screens and no duplicate menus.
- Add one small unobtrusive status chip: "Online" or "Offline - Preloaded Content".
- The popup appears only when an online navigation request cannot proceed because of connectivity.
- Arabic and Urdu RTL and English LTR must stay correct, with no clipped, overlapping or truncated text.
